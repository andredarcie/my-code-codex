# Carreira

O que eu aprendi sobre crescer como desenvolvedor backend .NET. C# e .NET são o ponto de partida; o que diferencia vem depois: saber construir, operar e trabalhar em time.

## O que mais importa

- **O básico bem feito vence o exótico.** APIs bem desenhadas, banco de dados e trabalho em equipe resolvem a maior parte dos problemas reais. Microsserviços e arquiteturas sofisticadas vêm depois, quando o problema pede.
- **Comportamento pesa tanto quanto técnica.** Comunicação, senso de dono e code review são o que faz o seu trabalho render no time. Ver [Soft skills](../soft-skills/).
- **Testes não são opcionais.** Com agentes de IA escrevendo código, são a forma de saber se o que foi gerado faz o que deveria. Ver [Testes](../testes/).
- **Quem escreve o código cuida dele em produção.** Observabilidade, pipeline e deploy fazem parte do trabalho. Ver [Observabilidade](../observabilidade/) e [DevOps](../dev-ops/).
- **Algoritmos ainda caem em entrevista**, sobretudo em empresas grandes, mesmo aparecendo pouco no dia a dia. Ver [Entrevistas técnicas](./entrevistas.md).

## Júnior, pleno e sênior

A diferença não é tempo de casa, é o escopo do problema que você resolve sozinho. Escrevi a versão longa em [A diferença entre desenvolvedor júnior, pleno e sênior](https://dev.to/andredarcie/a-diferenca-entre-desenvolvedor-junior-pleno-e-senior-na-minha-opiniao-pt-br-659).

| | Resolve sozinho | Precisa de ajuda para |
| --- | --- | --- |
| Júnior | tarefas bem definidas | quebrar o problema e decidir o caminho |
| Pleno | funcionalidades inteiras, do banco à API | decisões que afetam outros times |
| Sênior | problemas ambíguos, de ponta a ponta, incluindo produção | quase nada técnico; o desafio vira alinhar pessoas |

## Inglês

Inglês abre as oportunidades que pagam em dólar ou euro. Ler documentação é o mínimo; para trabalhar com time de fora, conversar numa daily e defender uma decisão técnica numa entrevista de uma hora. A forma mais eficiente que conheço: fazer em inglês o que você já faz (README, mensagens de commit, descrições de PR) e praticar conversação técnica toda semana.

## IA no dia a dia

Para o dev backend, trabalhar com IA significa usar agentes de código sem terceirizar o julgamento: escrever os testes que definem o comportamento, revisar o que o agente gerou como revisaria o PR de um colega e entender o suficiente para saber quando ele está errado. Escrevi sobre isso em [O mínimo que você precisa saber para desenvolver software com IA](https://dev.to/andredarcie/o-minimo-que-voce-precisa-saber-para-desenvolver-software-com-ia-1dc9).

## Portfólio

Experiência se prova com o que você construiu e publicou:

- Um projeto pequeno, completo e publicado vale mais que dez tutoriais pela metade: API com testes, Docker, pipeline e README que explica as decisões.
- GitHub com histórico de commits legível.
- Textos técnicos: explicar algo por escrito mostra domínio e comunicação ao mesmo tempo.
